# 安装脚本：交互界面、语言、监听网卡与管理命令

- 日期：2026-11-07
- 前置：[nodes-and-installers](2026-11-07-nodes-and-installers.md)（`install-control.sh`、节点部署脚本 `relay.sh`），以及本分支已有的 `--listen` 与端口检查。
- 评审：已按设计评审修订，见 §9。
- 已定：交互控件用脚本内置的 sh 菜单（方向键选择），不下载 gum 等外部程序；安装后在服务器上留下管理命令，无参数运行即打开菜单（状态、升级、重新配置、卸载）。

## 1. 现状与问题

- 两个脚本各自实现了提问：`install-control.sh` 有 `ask` / `choose` / `ask_password`（编号输入），`relay.sh` 直接 `printf` + `read`。界面只有英文，没有颜色、标识与汇总。
- 监听地址只能在“127.0.0.1 / 所有网卡”（控制面，以及刚加的 Docker 网桥）之间选；节点只能用 `--listen` 参数。SafeLine 这类拒绝回环上游的代理需要用户自己知道该填什么。
- 升级控制面要重新下载新版本的 `install-control.sh` 再运行；节点有 `yttt-relay-install --upgrade|--uninstall`，但用的是安装时那份脚本的逻辑，控制面更新了脚本也用不上。

## 2. 共享的界面库 `ui.sh`

两个脚本分开发布：`install-control.sh` 是 GitHub Release 附件，`relay.sh` 由控制面 `include_str!` 后下发。它们都必须是单个文件（`curl … | sh` 或下载后 `sh`），所以界面库不能运行时加载：

- 源文件 `packaging/installer/ui.sh`，原样复制进两个脚本的 `# >>> ui.sh` 与 `# <<< ui.sh` 标记之间。
- `scripts/sync_installer_ui.py`：默认检查两份副本与源文件一致（不一致则失败并提示），`--write` 时改写。CI 的 release-tools 检查里运行它，防止两份副本漂移。
- 脚本因此仍可直接阅读、直接运行（测试时用 `--asset-dir` / 改占位符，与现在相同）。

界面库只用 POSIX sh、`stty`、`dd`、`printf`，在 dash、bash、busybox ash 下都能运行。

### 2.1 三种模式

| 模式 | 条件 | 行为 |
|---|---|---|
| 富交互 | 能打开 `/dev/tty`、`stty` 可用、`TERM` 不是 `dumb`、没有 `--yes` | 颜色、标识、方向键菜单、隐藏输入 |
| 朴素 | 有终端但不满足上面任一条件 | 编号列表 + 输入行（现在的方式），无颜色 |
| 无人值守 | `--yes` 或没有终端 | 不提问，用参数与默认值；缺必填项时报错并给出对应参数 |

- 颜色只在富交互模式且未设 `NO_COLOR` 时使用。
- 字符集：`locale charmap` 为 UTF-8（或 `LC_ALL`/`LC_CTYPE`/`LANG` 含 UTF-8）时用 `❯ ╭─╮ ✔ ✘` 等符号，否则全部用 ASCII（`> +-+ ok x`）。
- 退出（含 Ctrl-C、`die`）时恢复 `stty` 设置与光标（`trap … EXIT INT TERM`），不会把终端留在无回显状态。

### 2.2 语言

- 第一个问题是语言（English / 中文），默认值来自 `LC_ALL` → `LC_MESSAGES` → `LANG`，以 `zh` 开头即中文。参数 `--lang en|zh` 或环境变量 `YTTT_LANG` 跳过这个问题；无人值守模式按环境决定。
- 终端不是 UTF-8 时只用英文，不显示语言菜单（中文在这种终端里是乱码）。
- 文本查表：`t KEY [参数…]`，每个脚本定义 `msg_en KEY` / `msg_zh KEY` 两个 `case`，`%s` 依次替换参数。界面库自己的文本（“↑↓ 移动 · 回车确认”、“两次密码不一致”等）在 `ui.sh` 里。
- 翻译的是提问、选项说明、提示、警告与错误；参数名、路径、命令、服务日志不翻译。

### 2.3 控件

- `ui_banner 标题`：ASCII 字符画标识 `yttt`、版本号、标题（“控制面安装” / “relay 节点”）。宽度不足 60 列时只显示一行标题。
- `ui_select VAR 标题 默认值 "值|名称|说明" …`：
  - 富交互：`❯` 标记当前项，↑/↓（以及 `k`/`j`）移动，数字键直接跳到该项，回车确认；`Esc`/`q` 取消（等同 Ctrl-C，退出并恢复终端）。只重绘菜单所在的几行（光标上移后覆盖），不清屏，之前的问答留在屏幕上。
  - 选定后折叠成一行 `✔ 标题：名称`。
  - 朴素：编号列表 + `选择 [默认 N]:`。
  - 变量已由参数设置时不提问（与现在的 `choose` 相同）。
- 读按键：`stty -icanon -echo min 1 time 0` 后用 `dd bs=1 count=1` 逐字节读；读到 `ESC` 后用 `stty min 0 time 1` 再读两字节，区分方向键与单独的 `Esc`。
- `ui_input VAR 提示 默认值 [校验函数]`：校验失败时显示原因并重问。
- `ui_secret VAR 提示`：隐藏输入，输两次，不一致重问。
- `ui_confirm 提示 默认(yes|no)`：是/否两项的 `ui_select`。
- `ui_step` / `ui_ok` / `ui_warn` / `die`：步骤与结果行，带颜色与符号。
- `ui_spin 说明 命令…`：长操作（拉镜像、下载、等待服务就绪）时显示转圈，命令输出写入临时日志；失败时打印日志最后 20 行。非富交互模式下只打印一行说明。
- `ui_box 标题 行…`：结束时的汇总框（地址、管理员、下一步），中文按字符数而不是显示宽度对齐时会错位，所以汇总框只画左边线，不画右边框。

## 3. 监听地址：选网卡

控制面“只启动服务”与节点“在代理之后”都需要选监听地址；无域名的节点需要选端口。统一用 `ui_listen VAR 默认端口`：

1. 列出候选（来自 `ip -4 -o addr show`，没有 `ip` 时只列 127.0.0.1 与 0.0.0.0）：
   - `127.0.0.1` 仅本机：同机的 nginx 等代理。
   - `docker0` 的地址 Docker 网桥：仅本机与容器能访问；SafeLine 等拒绝回环上游的代理用它。
   - 其他每块网卡：`ens17  10.0.242.11`，说明里标出内网（RFC 1918、100.64/10）或公网。
   - `0.0.0.0` 所有网卡。
   - 自定义地址：输入 `地址`，校验是本机地址或 0.0.0.0。
   - 跳过 `veth*`、`br-*` 等 Docker 自建网桥与没有 IPv4 的网卡。
2. 默认项：检测到 SafeLine（有 `safeline-` 开头的容器）且有 `docker0` 时默认 Docker 网桥，否则默认 127.0.0.1。选所有网卡或公网网卡时额外提示“任何人都能直接访问，绕过代理”。
3. 再问端口（默认控制面 8080、节点 3340），立即检查占用：被别的程序占用时显示占用者并重问；被本安装自己的服务占用（`yttt-control`、`yttt-relay`、本安装的 `docker-proxy`）视为可用。
4. 参数 `--listen 地址:端口` 跳过这两个问题，仍做占用检查。

节点新增 `--port`（无域名时的端口，默认 3341，传给 `yttt-relay enroll --port`），同样检查占用。

## 4. 管理命令

### 4.1 控制面：`yttt-control-install`

- 安装、升级、重新配置成功后，把正在运行的脚本（版本号已填好）复制为 `/usr/local/bin/yttt-control-install`（0755）。卸载时一并删除。
- 无参数运行：标识 + 状态 + 菜单。
  - 状态：版本、安装方式、数据库、对外方式、监听地址、`public_url`、健康检查结果（`/healthz`）、Caddy 与同机节点是否在运行。
  - 菜单：升级、重新配置、卸载、退出。
- 升级：
  1. 取最新版本号：请求 `https://github.com/yuWorm/yttt/releases/latest`，读跳转地址里的标签；`--version X` 指定版本（可用于回到某个版本的安装逻辑，不做数据库降级）。
  2. 与当前版本相同：提示已是最新，可选择“仍然重新安装当前版本”（修复被改坏的文件）。
  3. 下载该版本的 `install-control.sh` 与 `SHA256SUMS`，校验后 `exec sh 新脚本 --upgrade --lang 当前语言`。真正的升级由新版本的脚本完成，这样新版本对安装布局的改动（新配置项、新的 unit）随升级生效。新脚本最后把自己装成新的管理命令。
- 重新配置、卸载：与现在的 `--reconfigure`、`--uninstall [--purge]` 相同，只是走新界面。卸载前列出将删除的内容并要求确认；`--purge` 另外确认一次“删除数据库与秘密，无法恢复”。
- 0.5.0 的安装没有管理命令：运行新的 `install-control.sh` 时识别出已有安装，菜单与上面相同，升级后装上管理命令。

### 4.2 节点：`yttt-relay-install`

- 现有命令保留，无参数运行时显示标识 + 状态 + 菜单：
  - 状态：节点 ID、地址、安装方式、监听地址、二进制或镜像版本、健康检查、QUIC 证书是否就位（在代理之后时）。
  - 菜单：升级、更改监听地址（仅在代理之后的节点）、卸载、退出。
- 升级：从控制面取当前的 `relay.sh`（`$CONTROL/install/relay.sh`，信任来自 HTTPS，与下载 relay 二进制相同），`exec sh 新脚本 --upgrade --lang 当前语言`，由新脚本换二进制或镜像并把自己装成新的 `yttt-relay-install`。控制面不可达时报错，不降级为用旧脚本。
- 更改监听地址：走 §3 的选择，改写 `relay.toml` 的 `listen`，重启服务或容器，做健康检查。不需要重新登记。
- 卸载：列出将删除的内容并确认。

## 5. 兼容与参数

- 现有参数全部保留，含义不变；新增 `--lang en|zh`、节点的 `--port`、控制面的 `--version`（管理命令升级时）。
- `--yes` 的行为不变：不提问，缺必填项报错。错误信息按所选语言输出（无人值守时按环境）。
- 部署命令（控制台生成的 `curl … && sudo … sh /tmp/yttt-relay-install.sh --domain …`）不变：脚本哈希在命令里固定，新脚本照常校验。

## 6. 不做

- 不用 gum、whiptail、dialog 等外部程序；不做全屏 TUI。
- 不翻译服务日志、控制台以外的输出格式（JSON、配置文件）。
- 不做控制面数据库降级；`--version` 指向旧版本时只是用旧版本的脚本逻辑重新安装该版本的程序。

## 7. 测试

- `shellcheck -S warning` 两个脚本与 `ui.sh`；`sync_installer_ui.py` 检查。
- 容器内（debian、alpine 的 busybox ash）：
  - 无人值守：现有的安装、升级、重新配置、卸载矩阵，加端口占用与 `--listen`、`--port`。
  - 朴素模式：`TERM=dumb` 下用 `script` 提供终端，按编号回答。
  - 富交互：`script` 提供终端，送入方向键转义序列与回车，检查选中值、`stty` 退出后恢复、Ctrl-C 中断后恢复。

## 9. 评审修订

以下各条优先于前文。

- **交接只传已有参数**：语言经环境变量 `YTTT_LANG` 传给新脚本，不加 `--lang`；交接参数只用旧脚本也认识的 `--upgrade`、`--dir`（以及测试用的 `--asset-dir`、`--image`）。脚本带 `# yttt-installer-protocol: 1` 标记，以后新增交接参数时只传给声明了更高协议的脚本。
- **记住安装位置**：控制面把安装目录写进 `/etc/yttt-control/install-location`，管理命令据此传 `--dir`；`exec` 前显式恢复终端、删除临时目录（`exec` 不触发 EXIT trap）。
- **拒绝降级**：版本号用纯 sh 逐段比较（不用 `sort -V`）。目标版本低于已安装版本时拒绝（数据库迁移会让旧程序无法启动），`--force` 才放行并警告。`relay.sh` 也带 `__VERSION__`（控制面下发时填入自己的版本），节点从控制面取到的脚本比自己旧时同样拒绝。
- **节点只经 HTTPS 换脚本**：控制面地址是 `http://` 时拒绝自动换脚本（中间人能以 root 执行代码），`--allow-http` 才放行。文档写明 `SHA256SUMS` 与脚本同源，只防截断不防篡改；信任来自 HTTPS。
- **管理命令总是更新为当前脚本**：安装、升级时，只要已装的 `yttt-relay-install` / `yttt-control-install` 与当前脚本内容不同就覆盖。`$0` 不是脚本文件（`curl | sh`）时改为下载对应版本的脚本再安装。0.5.0 的节点需要一次性运行新的 `relay.sh --upgrade`（文档写明命令）。
- **没有终端时不改变行为**：无 `--yes` 且无终端仍报错退出；管理命令无参数且无终端时只打印状态。
- **按键与重绘**：
  - 读键用 `dd bs=1 count=1 | od -An -tu1` 比较字节值（回车 13/10、ESC 27）。
  - ESC 之后等待 0.3 秒再读，兼容 SSH 延迟；识别 `ESC [ A/B` 与 `ESC O A/B`，吞掉 `ESC [ 5 ~` 这类长序列的余下字节。单独的 Esc 不退出（`q` 与 Ctrl-C 退出）。
  - 所有 `stty` 都 `</dev/tty`；进入前保存 `stty -g`，退出时原样恢复。
  - 绘制菜单时关闭自动换行（`\033[?7l`，退出时恢复）、每行 `\033[K`，选项文字按字节截断，避免换行打乱光标上移的行数。
  - 只在 `/dev/tty` 上画界面；标准输出被管道接走（`| tee`）不影响菜单。
- **统一的清理链**：`ui.sh` 提供 `ui_on_exit 命令`，两个脚本与下载函数都登记到同一条清理链，不再各自覆盖 EXIT trap；INT/TERM 处理后退出（130/143）。非交互阶段忽略 SIGHUP，SSH 断开不会中途打断安装。
- **私有变量**：`ui.sh` 的内部变量一律 `_ui_` 前缀，在 `set -eu` 下测试。
- **字符集与语言**：没有 `locale` 命令（Alpine）时看环境变量；`LANG=C` 等非 UTF-8 环境下语言菜单仍显示，用 ASCII 写作 “English / Zhongwen (UTF-8 terminal)”，选中文且终端不是 UTF-8 时提示改用 UTF-8 终端并退回英文。`sudo` 会清掉环境变量，提示里给 `--lang zh`。
- **端口归属**：
  - “本安装自己的”占用：进程是 `yttt-control`、`yttt-relay`、`caddy`（本安装的 Caddy），或是 `docker-proxy` 且端口等于保存的 `LISTEN` 端口。重新配置时恢复端口检查，按上面识别自己的占用。
  - 冲突按地址判断：同一地址，或任一方是 `0.0.0.0` / `[::]` 才冲突。
  - 没有 `ss` 时用 `netstat -ltnp`（busybox）；都没有时警告“无法检查端口”而不是当作空闲。
- **同机节点**：`colocate_relay` 显式传 `--listen 127.0.0.1:3340`；同机节点（Caddy 转发）的管理命令不提供“更改监听地址”。节点是否在代理之后从 `relay.toml` 的 `[quic_tls]` 判断，安装方式之外也记进 `install.env`（`PROXIED=1`）。
- **IPv6 与校验**：自定义地址接受 `[IPv6]:端口`，按 `ip -6 addr` 校验；没有 `ip` 时接受并警告。
- **占位符**：`ui.sh` 里不出现 `__VERSION__`、`__CONTROL_URL__`、`__IMAGE__`，注释也不写。同步检查放进每个 PR 都跑的校验工作流。
- **最新版本**：从 `releases/latest` 的跳转取标签，必须匹配 `^v[0-9]+\.[0-9]+\.[0-9]+$`；跳到 `/releases`（没有发布）时报错。
- **sudo 路径**：提示里写完整路径 `/usr/local/bin/yttt-control-install`（部分发行版的 `secure_path` 不含 `/usr/local/bin`）。
