# 控制台第二版：可运营的管理端与重做的界面

基于在 luoliyun-hk-2h4g 上的真实部署，用浏览器逐页检查（登录、注册、概览、设备、用量、账号、管理总览、账号管理、账号详情、节点、套餐、审计日志）后的结论与方案。

## 1. 检查结论

### 1.1 功能缺口（运营一个付费 relay 时会卡住的地方）

| # | 缺口 | 现状 | 后果 |
|---|---|---|---|
| G1 | 套餐不能在控制台管理 | `[[plans]]` 写在配置文件，启动时 upsert；页面只读，提示“重启后生效” | 改价、加套餐都要登服务器改文件重启；配置会覆盖控制台的任何改动 |
| G2 | 注册设置不能在控制台管理 | `[signup]` 的开关、默认套餐、默认节点在配置文件 | 关注册、换新用户落地节点都要重启 |
| G3 | 管理员不能建账号、不能重置密码 | 只有自助注册；没有邮件 | 用户忘记密码就永久锁死；关注册时无法开户 |
| G4 | 没有按天的用量 | 只有 `usage_months` | 画不出趋势；排查“谁在今天跑满了”无从下手 |
| G5 | 节点看不到流量 | 节点只有在线设备数 | 不知道哪个节点负载高，迁移账号没有依据 |
| G6 | 节点 / 套餐没有说明字段 | 只有 ID | 用户概览里只看到 `basic`、`hk-1` 这类内部 ID |

### 1.2 界面问题

- 内容区固定 `maxWidth: 1200` 左对齐，宽屏右侧大片空白；页面背景与卡片同为白色，没有层次。
- 顶栏只有一行文字和“退出登录”，没有面包屑、头像、主题切换；侧栏品牌只是纯文本。
- 统计卡片是纯文字数字，没有图标、趋势、颜色区分；用量只有一条进度条。
- 空状态是表格自带的“暂无数据”，没有插画和下一步引导（设备页尤其需要告诉用户怎么登记设备）。
- 登录 / 注册是悬在白底中间的一张小卡片，没有品牌区。
- 弹窗承载复杂表单（新建节点、编辑），信息挤；Semi 更适合用 SideSheet。
- 没有暗色模式。

## 2. 方案

### 2.1 后端

**套餐由数据库做唯一来源（G1、G6）**

- 迁移 0003：`plans` 增加 `name`、`description`、`archived BOOLEAN`、`sort INTEGER`、`created_unix`。速率仍是 `INTEGER`（上限约 2 Gbps）：节点协议里速率是 `u32`，单账号用不到更高。
- 启动时 `[[plans]]` 只在 `plans` 表为空时写入（与节点相同），之后以控制台为准。配置文件里的套餐降级为“首次启动种子”，文档同步说明。
- 接口：
  - `POST /v1/admin/plans` 新建；`PATCH /v1/admin/plans/{id}` 修改任意字段；
  - 归档 / 恢复走 PATCH `archived`；有账号在用时不能删除，`DELETE` 仅对零账号的套餐开放。
- 生效：速率、额度在节点下一次上报（约 15 秒）时生效，因为 `node_usage` 每次都从库里读套餐；设备上限只限制新登记，已有设备保留。
- 每项修改写审计日志（含修改前后的值）。

**运营设置进数据库（G2）**

- 迁移 0003：单行表 `settings(signup_enabled, signup_plan, signup_node)`；`[signup]` 只在表为空时写入。
- `GET/PATCH /v1/admin/settings`；校验套餐未归档、节点为 active。
- `create-admin` 改为读 settings（无行时读配置）。

**管理员开户与重置密码（G3）**

- `POST /v1/admin/accounts` {email, password, plan, node, role}。
- `POST /v1/admin/accounts/{id}/password` {password}：设置新密码并注销该账号所有会话；不能对自己用（自己走“修改密码”）。
- 均写审计日志，日志里不含密码。

**按天用量与节点流量（G4、G5）**

- 迁移 0003：`usage_days(account_id, day INTEGER /* 自 Unix 纪元起的 UTC 天数 */, node_id, upstream_bytes)`，主键 (account_id, day, node_id)。
- `node_usage` 在累加 `usage_months` 的同一事务里累加 `usage_days`。
- 接口：
  - `GET /v1/accounts/me/usage/daily?days=30`
  - `GET /v1/admin/usage/daily?days=30`（全站按天合计）
  - 节点列表增加 `month_bytes`（本月经该节点转发的字节）。

### 2.2 前端（Semi Design 2.104）

整体：

- 布局：`Layout` + 可折叠 `Nav` 侧栏（品牌 logo + 名称）；顶栏放面包屑、主题切换（`body[theme-mode=dark]`）、头像下拉（账号、退出）。内容区灰底（`--semi-color-fill-0`），卡片白底，宽度自适应，`Row/Col` 栅格。
- 统一 `PageHeader`：标题、说明、右侧操作按钮。
- 空状态统一用 `Empty` + `@douyinfe/semi-illustrations`，并给出下一步。
- 复杂表单改用 `SideSheet`；确认用 `Modal.confirm`。
- 图表：`@visactor/react-vchart` + `@visactor/vchart-semi-theme`（Semi 官方推荐，跟随明暗主题），只在用量与总览页按需加载，不进首屏。

页面：

| 页面 | 改动 |
|---|---|
| 登录 / 注册 | 左右分栏：左侧品牌区（产品一句话、三条卖点：端到端加密、直连优先、按量计费），右侧表单 |
| 概览（用户） | 顶部 4 张统计卡（本月用量、设备数、当前速率、节点状态），30 天用量面积图，套餐卡片（名称、说明、额度），“三步开始使用”`Steps` |
| 设备 | 空状态引导；列表显示名称、设备密钥（可复制、截断）、登记时间，删除二次确认 |
| 用量 | 30 天柱状图 + 12 个月表格，额度线 |
| 账号 | `Descriptions` 账号信息；修改密码表单 |
| 管理总览 | 统计卡（账号、今日新增、本月转发、在线设备、在线节点 / 总数）；30 天全站转发趋势；节点状态表 |
| 账号管理 | 搜索 + 套餐 / 状态筛选；“新建账号”SideSheet；行内显示用量占额度百分比 |
| 账号详情 | 头部（邮箱、标签、操作按钮组：改套餐、迁移节点、重置密码、封停、管理员）；30 天用量图；设备表 |
| 节点 | 每行增加本月流量；新建 / 编辑用 SideSheet；部署命令弹窗保留（一键复制） |
| 套餐 | 卡片网格（名称、说明、速率、额度、超额速率、设备上限、账号数、归档标记）；新建 / 编辑 SideSheet，单位用 Mbps / GB 输入，内部换算为 bps / 字节 |
| 设置（新） | 注册开关、默认套餐、默认节点 |
| 审计日志 | 按操作类型筛选；详情列展示修改前后 |

### 2.3 工程

- Semi 官方 skill（`semi-design-guide`）与 Semi MCP 用于查组件 API；安装由用户执行（见报告）。
- 新增依赖锁定精确版本，`npm ci` 构建；VChart 单独分包。
- 测试：控制面数据库测试覆盖套餐 CRUD 与生效、settings、管理员开户 / 重置密码、按天用量累加；前端 `tsc` + 构建；最后用 ego 浏览器在 HK 部署上逐页截图复查（亮 / 暗两种主题）。
- 部署：重新构建 x86_64 控制面，更新 HK 上的 compose（只替换控制面镜像，数据库保留）。

## 3. 不做

- 支付与自动开通（需要选支付渠道，单独设计）。
- 邮件找回密码（需要发信服务）。
- 多管理员角色细分（只有 admin / user）。
